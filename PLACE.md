# a performance is not its directory

A ritual used to get a worktree cut for it, so the tree and the performance were
one fact. Everything that needed to name a performance named its path: the
driver took a path, the reap selected agents by cwd, the agent bound itself by
cwd, the abort found a row by repo, the Stop briefing went to whoever stood in
that directory.

Making the tree optional split those two facts apart. A ritual that names no
`tree:` performs where the push happened — a checkout a person is working in,
holding their sessions, their agents, their files.

Every consumer keyed on place then meant something it did not mean.

> "why cant we assume that the agent is there, that the checked out repo that
> the branch its on is the correct one?"

## What the row already knew

`id`, `session`, `parent`, `agent_pid`. The identity was recorded and unused.

- `ground drive` takes the performance, not its tree
- the reap ends the session ground bound, not every background agent in a directory
- `bindAgent` writes `WHERE id = ?`; a session claims a performance only when
  `GROUND_PERFORMANCE` names it
- the Stop briefing reaches the session carrying the performance
- a tree is removed only when the ritual declared one

## What fires

`origin:` on a project makes the repo the identity, so every checkout of it
performs — the tree, a worktree, a clone made tomorrow. `path:` says where that
repo is on disk.

> "IF A DIRECTORY IS A REPO AND THAT REPO IS ALSO THE SAME REPO IN A PROJECT
> BLOCK / RITUALS DEFINED FOR ONE PROJECT SHOULD FIRE FOR GIT WORKTREE
> CHECKOUTS"

> "THE AGENT CANNOT NOT BE SUBJECT TO THE CONTROLS A RITUALS THAT FIRE FOR A
> GIVEN PROJECT."

`effectiveCwd` reads where git work happened: the last git invocation in the
command, through `-C`, unmoved by a pipe that follows it.

A push that the remote refused starts nothing. `refs/heads/<b>` and
`refs/remotes/origin/<b>` equal means it landed.

> "i dont want GROUND_CWD to matter, i dont want ritual writers to have to think
> about it"

> "rite writers should nevr have to think about it, or have to speciify it"

## What is said once

An ending. A performance ends once and the Stop that follows it announced it
again every turn.

> "RITUAL GOR ABORTED, WHY DO WE NEED TO RECEIVE A MESSAGE ABOUT IT EVERY
> FUCKING STOP EVENT"

## What is never dropped

`getBranch` answers null when there is no branch. `unknown` read as a branch all
the way to the box's ref.

`MAX_EVALS` bounds one eval at sixteen asks. An eval that answers the same
sixteen times reads a condition decided before the rite ran; ONBRANCH held a
session 103 turns.

> "i say bound eval to 16 as well if its the same eval"

> "if we do eval 16 times there is something wrong with how the ritual or rite
> is designed probably"

The floor a rite is given is `GROUND_SESSION_ID`, `GROUND_BRANCH`,
`GROUND_TOOL_INPUT`. `GROUND_CWD` is gone — a rite that cannot name a place
cannot leave the one it was given.

One token: `QNTX_TOKEN`, else `~/.qntx/token`.
